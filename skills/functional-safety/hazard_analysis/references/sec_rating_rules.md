# S/E/C 评级与 ASIL 判定规则（ISO 26262-3:2018 + SAE J2980）

本技能使用**数字评级**：S ∈ {0,1,2,3}、E ∈ {0,1,2,3,4}、C ∈ {0,1,2,3}。
ASIL 由渲染器按下方矩阵**确定性反算**，LLM 不输出 ASIL、只输出 S/E/C 与理由；
渲染器反算结果与评级冲突时仅在注释列标黄提示，不篡改评级。

## 一、严重度 S（Severity，参考 SAE J2980 碰撞速度/ΔV 锚点）

| S | 含义 | 典型锚点（伤害/碰撞能量，供判断，不是死规则） |
|---|---|---|
| S0 | 无伤害 | 车辆保持静止、无碰撞可能；或事件物理上不导致接触 |
| S1 | 轻微伤害，不危及生命 | 撞行人：3 < ΔV < 10 km/h；车车低速碰撞：10 < ΔV < 30 km/h |
| S2 | 严重（危及生命，可能存活） | 撞行人：约 10 ≤ v < 25 km/h；车车碰撞：约 30 ≤ ΔV < 60 km/h；或中速下可能的侧面/追尾伤害 |
| S3 | 致命/危及生命的严重伤害 | 撞行人：v ≥ 25 km/h；车车碰撞：ΔV ≥ 60 km/h；高速对向碰撞、翻滚、高速侧面碰撞 |

- 速度/ΔV 信息缺失时，依据伤害机理（碰撞对象、相对速度量级、约束状态）保守判断，并在理由中说明假设；
- 同一事件涉及多种碰撞对象时，按**最严重**可预见后果取 S。

## 二、暴露概率 E（Exposure，数字 0–4，E4 暴露概率最高）

| E | 含义 |
|---|---|
| E0 | 几乎不可能（不单独产生安全要求） |
| E1 | 非常低概率 |
| E2 | 低概率 |
| E3 | 中等概率 |
| E4 | 高概率（常见运行状态） |

- **每个场景的推荐 E 值直接查《运行场景库》**（scene_library.md），场景库已为 136 个场景标定 E 值；
- 一个危害事件由多个场景组合时，综合 E 取组合中的**最高 E 值（取大原则）**；
- 自行新增场景（scene_refs=CUSTOM）时，须在 E 理由中说明 E 值取值依据。

## 三、可控性 C（Controllability，数字 0–3）

| C | 含义 | 锚点（驾驶员/其他交通参与者能够避免伤害的比例） |
|---|---|---|
| C0 | 总体可控 | >99% 的驾驶员/参与者可通过常规动作（如刹车、转向）避免伤害；c_basis 常为「项目经验」 |
| C1 | 简单可控 | 90%–99% 可避免 |
| C2 | 通常可控 | 低于 90% 但多数人仍可控制 |
| C3 | 难以控制/不可控 | 反应时间不足、动作反直觉、物理上无法规避 |

- c_basis（可控性选择依据）取值建议：`项目经验` / `ISO 26262 参考` / `J2980 参考` / `实车数据`；
- 判断 C 时考虑：预警时间、驾驶员反应空间、路面附着、其他交通参与者避险能力、
  失效是否有征兆（如卡滞 vs 突发非预期）。

## 四、ASIL 查表矩阵（ISO 26262-3:2018, Table 4）

| | C1 | C2 | C3 |
|---|---|---|---|
| S1, E1 | QM | QM | QM |
| S1, E2 | QM | QM | QM |
| S1, E3 | QM | QM | A |
| S1, E4 | QM | A | B |
| S2, E1 | QM | QM | QM |
| S2, E2 | QM | QM | A |
| S2, E3 | QM | A | B |
| S2, E4 | A | B | C |
| S3, E1 | QM | QM | A |
| S3, E2 | QM | A | B |
| S3, E3 | A | B | C |
| S3, E4 | B | C | D |

特殊规则：
- **S=0 → QM**（无安全要求，不挂安全目标）；
- **E=0 → QM**（无论 S/C）；
- **C=0 → QM**（总体可控，不进上表）。

## 五、理由书写格式（必须便于审计，与示例工作簿一致）

- S 理由：以 `Sx:` 开头，先写碰撞/伤害依据，再写等级结论。多依据用 `//` 分隔。
  例：`与行人发生碰撞（3<ΔV<10）//S1:轻微受伤，不危及生命`
- E 理由：逐场景列出，格式 `E值:场景描述`，多个用 `//` 分隔。
  例：`E4:在车库停车//E4:启动过程（0<v<10km/h）//E4:道路旁边有行人`
- C 理由：c_basis 单独一列；C 理由先写规避动作分析，再以 `Cx:` 收尾。
  例：`驾驶员可以刹车来停止车辆//C0:总体来说是可控的，每个驾驶者都可以控制它`
- 沿用历史项目评级时，S/E/C 与三段理由**仍必须完整输出**（审计要求），
  并在 source 中标注历史来源。

## 六、边界

- HARA 只记录顶层 ASIL，不做 ASIL 分解（分解归 FSC/TSC 阶段）；
- 所有自动评级均为建议值，须经责任人逐条复核签署确认。
