# 相关项域前缀映射表（可编辑）

ID 编号规则（与「命名规则」sheet 一致）：

| 前缀 | 相关项域 | 典型系统 |
|---|---|---|
| P | powertrain 动力 | 驱动电机、电机控制器（逆变器）、减速器、动力域控 |
| CB | chassis Brake 底盘制动 | ESC、EHB/线控制动、EPB、制动助力 |
| CS | chassis Steering 底盘转向 | EPS、转向管柱、线控转向、后轮转向 |
| A | ADAS 智驾 | 感知传感器、ADAS 域控、AEB/LKA/ACC 功能 |
| B | body 车身 | 车门、车窗、灯光、雨刮、座椅、天窗 |
| T | thermal 热管理 | 电池热管理、空调、热泵、冷却回路 |
| HV | high voltage 高压 | 高压配电、OBC、DCDC、充电系统 |
| I | infotainment 信息娱乐 | 车机、仪表、HUD、音响 |
| XX | 无法判断时的占位 | 由人工在版本评审时修正 |

## 使用规则

1. 根据用户提供的相关项定义，从上表推断域前缀；推断时以相关项的**功能归属域**为准
   （线控转向 → CS，即使它带电机）。
2. 同一相关项确实跨域时，以主责域为前缀，并在功能清单备注中注明协作域。
3. 推断不出时一律使用 `XX` 占位（如 `XX_func_0001`），禁止臆造表外前缀；
   在版本管理/备注中提示人工修正。
4. **新增/修改域前缀时直接编辑本表即可**，提示词无需改动；编号器自动读取 JSON 中的
   `item.domain_prefix` 拼出全部 ID。

ID 拼接形式：

| 对象 | 形式 | 示例 |
|---|---|---|
| 整车功能 ID | `{前缀}_func_{功能4位序号}` | CS_func_0001 |
| 功能失效 ID | `{前缀}_MF_{功能4位序号}_{失效2位序号}` | CS_MF_0001_01 |
| 危害事件 ID | `{前缀}_hzrd_{功能2位序号}{事件3位序号}` | CS_hzrd_01001 |
| 中间安全目标 ID | `{前缀}_SG_{功能2位序号}{目标4位序号}` | CS_SG_010001 |
| 整车安全目标 ID | `{前缀}_SG_VH_{合并目标4位序号}` | CS_SG_VH_0001 |
